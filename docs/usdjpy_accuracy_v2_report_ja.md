# USD/JPY 精度改善V2 実装・検証報告書

作成日: 2026-09-19（JST）
対象: 短観・日米金利差を用いるUSD/JPYモデル
結論: 5段階の改善案をすべて実装した。ただし、事前に固定した昇格条件を満たす候補はなく、現時点では本番モデルへ昇格させず、RW下限アンサンブルをシャドー運用する。

## 1. 実装した5段階

### 1. 理論値乖離の収束モデル

予測起点より前に利用可能だったデータだけでローリング理論値を推定し、現値との対数乖離が次の四半期末までにどの程度収束するかを予測する。

```text
V_t = a_t + b_t × 日米10年金利差_t + c_t × 短観_t
予測値 = S_t × exp(λ × log(V_t / S_t))
```

`λ` は `{0, 0.25, 0.5, 0.75, 1}` に固定し、各起点より前に判明していた実績だけで選択する。

### 2. 変化率モデル

為替水準を直接回帰せず、次の四半期末までの対数変化率をリッジ回帰する。

```text
log(S_{t+1} / S_t)
  ← log(V_t / S_t), Δ短観_t, Δ日米10年金利差_t
```

リッジ強度は `{1, 10, 100}` の固定候補だけを使う。今回の厳格な履歴検証では、この候補が単体で最良だった。

### 3. 2年金利差・政策期待

政策期待の厳格候補には、ALFREDの当時ビンテージから復元した米日3か月インターバンク金利差を採用した。米国と日本で公表月がずれる場合は、両方に存在する最新の共通観測月だけを使う。

```text
log(S_{t+1} / S_t)
  ← log(V_t / S_t), Δ短観_t, Δ米日3か月金利差_t
```

米日2年国債金利差も同型で実装した。ただし日本の過去2年金利は財務省の現行全履歴であり、初回公表ビンテージを完全には復元できない。このため2年差候補は診断専用とし、アンサンブル、Holm補正、昇格判定から除外した。前向き運用では取得時点の原本を保存する。

### 4. 動的係数

日米10年金利差と短観の係数を固定せず、割引因子カルマンフィルターで緩やかに更新する。

```text
S_{t+1} = α_t + β_t × 日米10年金利差_t + γ_t × 短観_t + ε_t
```

割引率は `{1.00, 0.99, 0.97, 0.94}` の固定グリッドから、過去に判明済みの目的変数だけで選ぶ。

### 5. RW下限アンサンブル

ランダムウォーク、理論値収束、変化率、3か月政策期待、動的2要因の5候補を、非負・合計1で統合する。直近12件の逆MSEウェイトを固定事前ウェイトへ50%縮小し、ランダムウォークの比率を35%以上に固定した。事後的に最良の単体候補を選び直す方式にはしていない。

## 2. 過度なフィッティングを避ける仕組み

- 説明変数、変換、ハイパーパラメータ候補、最終シャドーモデル、昇格条件をプロトコルに事前固定した。
- 各予測起点で利用可能だったデータだけを使う。四半期末の目的変数は期末+10日後から利用可能とする。
- 外側の時系列検証だけでなく、内側の各疑似起点でも未公表の目的変数をpurgeする。
- 各候補は自分に必要な変数だけで学習標本を作り、無関係な系列の欠損で標本を狭めない。
- ハイパーパラメータ探索範囲を小さな固定グリッドに限定した。
- 2年差の履歴候補はデータ強度が不十分なため診断専用とした。
- 一部の予測期間が重なるため、DM検定はNewey–Westラグ1を使った。
- 複数候補の比較にはHolm補正を適用した。
- 履歴結果だけでは自動昇格させず、同一仕様の前向き成績を必須とした。

## 4. 判定

単体では変化率リッジが最良で、対応RW比のRMSEを4.49%、MAEを7.09%改善した。しかし事前基準のRMSE 5%以上には届かず、統計的な優位性も確認できない。

事前指定のRW下限アンサンブルはRMSEを3.75%、MAEを4.42%改善したが、前半期間では3.05%悪化した。よって「改善した可能性」はあるものの、「安定して予測力がある」とはまだ判定しない。

昇格には次をすべて要求する。

1. 前向きの対応済み予測が20件以上
2. ランダムウォーク比でRMSEが5%以上改善
3. MAEも改善
4. 前半・後半の両方でRMSEが非悪化
5. Holm補正済みDM p値が0.10以下
6. 人間による最終レビュー

現時点の昇格候補は0件である。

## 5. 前向き検証と毎日実行する機構

Codex automation `ドル円前向き検証・精度改善V2 日次実行` を有効化した。毎日09:40 JSTに、次の順序で動く。

1. 基礎台帳と保存原本を事前検証
2. FRED・日銀の新規データを取得し、新しい短観なら基礎予測を一度だけ発行
3. 基礎台帳を再検証
4. V2台帳、固定履歴基盤、原本、学習bundle、既存予測・採点算術を事前検証
5. 当日ビンテージの3か月系列と任意の2年系列を保存
6. 同日最初の入力イベントだけでV2シャドー予測を一度だけ発行
7. 新しい実績が利用可能なら採点し、全件を再検証

事前検証に失敗した系統は更新しない。3か月政策系列、台帳、固定履歴基盤、原本、学習bundleの異常はfail-closedで新規発行を止める。2年系列だけの欠損は診断を`degraded`にするが、厳格アンサンブルの発行は妨げない。

2026-09-19時点でV2状態は`ok`、前向き予測0件、採点0件である。これは次回の新しい短観をまだ観測していないためで、初回予測から追記専用台帳へ蓄積する。基礎系の日次取得は完了しているが、同日時点のFRED為替観測は2026-09-11で内部鮮度上限7日を1日超えたため、基礎ステータスには`degraded`警告が残る。V2の新規予測は発行されていない。

## 7. データ上の限界

- 履歴の目的変数は、利用可能日を制限した最終DEXJPUS値であり、初回公表ビンテージそのものではない。保存済みビンテージとの比較では対象値の差を検出していない。
- ALFREDの履歴指定は日付粒度であり、時刻粒度ではない。短観公表日の前日を市場情報の保守的な締切とした。
- 日本2年国債利回りの履歴は現行全履歴であり、厳密なリアルタイム履歴候補には使えない。
- OOS標本は25〜26件と小さく、レジーム依存と多重比較の不確実性が大きい。
- この仕組みは検証・研究用であり、売買の自動執行は行わない。
