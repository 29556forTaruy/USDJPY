# USD/JPY ハイブリッド予測・ポジションモデル V1

このフォルダは、既存の四半期USD/JPYモデルと、
[`29556forTaruy/forex-fear-and-greed`](https://github.com/29556forTaruy/forex-fear-and-greed)
の市場データを組み合わせた、**研究専用・シャドー運用専用**のモデルです。
注文を発注する機能はありません。

## まず結論

モデルの仕組みと日次運用機構は完成していますが、初回バックテストでは
「変化なし」予測を上回れず、ポジション損益もマイナスでした。そのため、
実運用へ昇格させず、前向き検証だけを続けます。最新の数値と判定は
`results/REPORT.md`、機械可読な最新シグナルは `results/current_signal.json` にあります。

## 初心者向けに一言でいうと

四半期モデルを「遠くの目的地」、日々の恐怖指数と移動平均を「今の風向き」、
年足ピボットを「途中にある壁」として使います。三つの時間軸が十分に同じ方向を
向いたときだけポジションを持ち、相場が荒いときや壁が近いときはサイズを減らします。

```text
四半期マクロ・アンカー ─┐
監査版F&G               ├─ 1日・5日・20日予測 ─ 合意とコスト判定 ─ 目標ポジション
移動平均20/50/125/200日 ┤                                  │
前年OHLCの年足ピボット ─┘                  ボラ・相場状態・DD・損失後制限
```

## 1. 何を予測するか

1日、5日、20日先の対数変化率を、その時点のボラティリティで割った値を予測します。
例えば予測が `+0.5` なら「その期間の通常の値動きの半分ほど円安・ドル高方向」
という意味です。レートそのものを直接当てるより、異なる相場環境を比較しやすくなります。

各期間で次の4候補を作ります。

- `random_walk`: 変化なし。最も単純な基準です。
- `macro_ridge`: 四半期アンカーとの乖離だけを主に使います。
- `technical_ridge`: F&G、移動平均、ピボット、相場状態を使います。
- `hybrid_ridge`: マクロとテクニカルを一緒に使います。

最終予測は4候補のアンサンブルです。ただし、単純モデルを無視して複雑化しないよう、
`random_walk` の重みを最低35%残します。係数は毎月一度だけ更新し、学習窓は756～1,260行、
ridgeの強さは `{1, 10, 100}` だけからpurged時系列CVで選びます。

## 2. 恐怖指数をどう監査したか

元リポジトリのヘッドライン値は0が恐怖、100が強欲です。ただし、そのまま学習には
入れていません。監査版 `audited_market_fng` は次の4成分だけを、各時点までの履歴で
再計算します。

- momentum: USD/JPYが125日移動平均より強いか
- strength: 過去52週レンジのどこにいるか
- realized volatility: 値動きが静かか荒いか（荒いほど恐怖側）
- risk regime: AUD/JPY、日経、S&P 500、VIXのリスク選好

次の3成分は監査版から除外しました。

- COT: 円先物とEUR/JPYクロス先物が混ざる可能性と、火曜日データを金曜日公表前に
  使う先読みの可能性がありました。
- 金利差: 完全な初回公表ビンテージではなく、既存マクロモデルとも情報が重複します。
- breadth: 欠損したクロスを「上昇していない」と数える方向の偏りがあります。

元のヘッドライン値は比較診断として保存しますが、予測説明変数には使いません。

## 3. 移動平均と年足ピボット

移動平均は20、50、125、200日です。単純なゴールデンクロスだけでなく、
`価格/MA20`、`MA20/MA50`、`MA50/MA125`、`MA125/MA200` の対数距離を
その日のボラで割って使います。

年足ピボットは、当年の高値・安値を使わず、**完了した前年**の高値 `H`、安値 `L`、
終値 `C` だけで一年間固定します。

```text
P  = (H + L + C) / 3
R1 = 2P - L        S1 = 2P - H
R2 = P + H - L     S2 = P - H + L
```

これにより、後から判明した当年高値を過去の予測へ混ぜる先読みを防ぎます。

## 4. 乖離率からポジションを作る順序

1. 1・5・20日予測を20%・40%・40%で合成します。
2. 少なくとも2期間が同方向であることを要求します。
3. 売買コストを予測強度から先に引きます。
4. 新規は0.20σ以上、継続は0.10σ以上というヒステリシスを使います。
5. 強度0.80σでフルサイズ相当とし、年率ボラ目標5%で縮小します。
6. trend/range/overheat/stressの上限、近いピボット、日次0.25の変化幅で制限します。
7. 日次損失1%後は2判断分を0.25以内、DD 4%で半減、DD 6%でフラットにします。

ポジションは `-1` から `+1` の範囲です。`+1` は最大ドルロング、`-1` は最大ドルショート、
`0` は見送りです。当日終値で作ったシグナルは、次に取引可能な時点からだけ適用します。

## 5. 過学習を避ける仕組み

- 最初の検証前に `protocol.json` を固定し、後から変更していません。
- 学習には、予測日時までに答えが確定した行だけを入れます。
- CVでは予測期間の重なりをpurgeし、5営業日のembargoを置きます。
- 係数更新は月1回、特徴数・alpha候補・学習窓・閾値は限定しています。
- F&Gなし、移動平均なし、ピボットなし、マクロなしを別々に再学習します。
- 変化なし、MAクロス、ボラ調整済み常時ロングとも比較します。
- 成績が悪くても閾値を後付けで最適化せず、シャドー判定に残します。

実装上の `trend_score` 判定境界は `position.py` に固定した `0.50` です。初回protocolに
この一項の明記が漏れていたため、V1のコード既定値を変更せず、将来変更するなら別protocol
として登録します。

## 6. 履歴検証と前向き検証の違い

今回のF&G履歴は「現在リポジトリにある履歴ファイル」です。当時の各日に見えていた
初回公表版を完全復元したものではないため、履歴成績には改訂バイアスが残り得ます。
その弱点を埋めるのが前向き台帳です。

`run_shadow.py issue` は予測、入力bundle、protocol、結果ファイルのhashをSQLiteへ追記し、
更新・削除をトリガーで禁止します。同じ市場日の予測が既にあれば、同値なら再利用し、
違う値への上書きは拒否します。これから蓄積する成績が昇格判断の中心です。

## 7. 実行方法

この端末で使用したPythonは次です。

```bash
PY=/Users/itaru/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/bin/python3
```

整合性検査は次です。

```bash
$PY -m unittest discover -s hybrid_position_v1/tests -v
$PY hybrid_position_v1/run_shadow.py verify
```

フルバックテスト（4アブレーションを含む）は次です。

```bash
$PY hybrid_position_v1/run_backtest.py
```

日次更新は、必ず事前verifyが成功してからネットワークを許可して実行し、最後に再度
verifyします。

```bash
$PY hybrid_position_v1/run_daily.py verify
USDJPY_HYBRID_ALLOW_NETWORK=1 $PY hybrid_position_v1/run_daily.py run
$PY hybrid_position_v1/run_daily.py verify
```

日次処理は、許可したF&Gリポジトリをfast-forwardし、USD/JPY OHLCを取得し、
content-addressed入力bundleを作り、予測を更新し、初見シグナルを台帳へ追記します。
日次処理では重いアブレーションを再実行せず、直近のアブレーション表を保存します。

## 8. 主なファイル

- `protocol.json`: 初回検証前に固定した仕様
- `sync_sources.py`, `data.py`: 入力取得、正規化、hash検証
- `features.py`: 監査版F&G、MA、前年ピボット、マクロ乖離、目的変数
- `model.py`: ridge、purged CV、月次更新、アンサンブル
- `position.py`: 合意、コスト、ボラ目標、各種リスク制限
- `run_backtest.py`: 歩み値検証、比較、アブレーション、昇格判定
- `ledger.py`, `run_shadow.py`: 追記専用前向き台帳
- `run_daily.py`: verifyを挟んだ日次更新
- `results/REPORT.md`: 初心者向けの最新結果
- `results/current_signal.json`: 最新の予測レートと目標ポジション
- `state/shadow_status.json`: 日次監視用ステータス

外部F&Gリポジトリには取得時点で明示的なLICENSEファイルが見当たらないため、そのコードや
データをこのモジュールへ再配布せず、許可したローカルcloneを入力元として参照します。
